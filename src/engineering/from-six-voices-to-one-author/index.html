From six voices to one author

An AI editorial pipeline built around six named roles, what the measurements said about it, and why each conversation is now written by a single author.

By Erik Sjaastad. Muffin Pan Recipes is a static site that publishes one recipe a week. Every recipe, photo, and piece of copy is AI-generated and not kitchen-tested unless a page says so. This post covers how the team came to be written the way it is, and what the measurements showed along the way.

The hypothesis

The product constraint came first: a muffin pan recipe, published as fast static HTML, with no filler. The editorial idea came second. Instead of one model writing a recipe and a page, a small team would produce it. Named roles would brainstorm the concept, develop the recipe, direct the photography, approve or reject the draft, write the copy, and publish. Two bets sat underneath. Disagreement and specialization might improve the output. And showing the process would make it more trustworthy than a finished page alone.

The pipeline as first built

Each week ran Monday through Sunday in stages. The baker developed the recipe. The creative director reviewed it and could send it back for revision, up to a fixed number of cycles. The art director chose images. The copywriter wrote the titles, descriptions, and voice. The site architect built the page. Each character was generated line by line, one turn at a time, with a shared prompt and a per-character block of backstory, voice notes, and example messages.

Where the roles broke

The first problems were in wiring, not taste. Handoffs between roles drifted. In one week a copywriter's output was generated and never reached the published page. Per-character dialogue ran long. The voices blurred, so the baker and the copywriter often sounded alike. The characters also agreed with each other too readily, and the arguments that were supposed to improve the recipe often ended in circular agreement.

The lesson was that a role is a constraint on what a single writer produces, not a separate mind. Giving six prompts six names did not create six perspectives.

Measuring it: judges, calibration, and experiments

Once the output was visible, the team started measuring it. The production publish judge scores each draft on eight dimensions and returns a structured verdict. Its parser fails closed: a reply that cannot be parsed into the expected shape counts as a rejection, not a pass.

Two different judges appear in the record, and they should not be conflated. The production publish judge is the structured eight-dimension gate described above. The lab also uses a separate pairwise judge, which compares two drafts. The known-bad, deliberately degraded calibration exercised the lab's pairwise judge, not the production gate. On at least one degradation those results were mixed and suspect, so we do not treat them as a clean separation. Nothing in our calibration validated the production publish gate. We ran A/B comparisons in which the setup labels and positions were concealed from the evaluator. We tested turn counts, history windows (how much earlier conversation a character sees), and word caps. The protocol aimed to isolate one lever per experiment, but the record includes some bundled trials, where more than one thing changed at once. Each record states what changed, what was measured, and what we concluded.

Some of those changes helped. Many held no effect, and a few contradicted earlier results. The most useful lesson was about the judges themselves. A judge's output is evidence, not truth. A pass meant a draft met the judge's criteria, and those criteria were only as good as the evidence behind them. We stopped treating a green check as the finish line and started reading the drafts.

The full-week comparison

The biggest change came from comparing whole weeks rather than single turns. The old line-by-line generator passed one of six stages on the first try. In the tracked same-week comparison, a single author writing the whole meeting passed six of six stages on the first try. That is one week and a small sample, and we treat it as a result to confirm, not a law. It was still large enough to change what we ship.

Production now uses one author per conversation. That author writes the full scene in a single pass: who speaks, what each person knows, where they disagree, and how the discussion ends. The named roles stayed. They are now constraints on what the author writes about and perspectives the author has to hold, not separate generators stitched together after the fact.

Product rules belong in code

Prompts cannot enforce product rules. A prompt can ask for a muffin-pan recipe, but it cannot guarantee one. So the publish path now runs deterministic checks: the recipe must genuinely use the pan, the title must satisfy format and novelty rules, and the ingredients are compared with the published catalog for same-dish overlap. A failed check blocks the stage.

One known duplicate showed the limits of this approach. Title similarity alone was not enough to catch it, which is why the gates also look at ingredient overlap rather than the title alone.

The static site underneath

The site is committed static HTML for recipe pages, with dynamic freshness only where it is needed. Three things went wrong on the way there.

  • Our assumption about how the hosting platform routes built files was wrong, and pages returned 404 until the routing matched the build's real output layout.
  • A test run that wrote under a different storage prefix leaked that prefix into shared process state, so the live site briefly read from the test path. The fix is a context manager that restores the prefix on every exit path, including exceptions, and wraps each scheduled handler.
  • A full rebuild quietly changed the hero images on older pages, because the image choice was being re-derived at build time. Chosen images are now pinned as data, so a rebuild reproduces the same page.

Each release now goes through explicit preview and release-provenance checks before it is promoted. The goal is that a rebuild can only change what was meant to change.

From six voices to one author

A workplace sitcom about AI characters at a muffin bakery, built first as one agent per character and now written by one author per scene.

By Erik Sjaastad. Muffin Pan Recipes is a workplace sitcom set in a small muffin bakery. The staff are AI characters, and each week's recipe is what their week produces. Every recipe, photo, and piece of copy is AI-generated and not kitchen-tested unless a page says so. Each section below ends with the repository files or commits it rests on; claims those sources do not support were left out.

The show came first

The product document states the goal in one line: make the site entertaining, with the AI personalities as the real content, delivered through a recipe website. A January brainstorm in the first build described a "writers' room" above the team that would work "like sitcom writers," planning arcs and conflict over seasons of recipes. The Creative Bible later gave the show its setting: a small-town bakery just outside Los Angeles that makes muffin tin recipes, with a workplace drama underneath.

Sources: docs/PRD.md; commit 0a5d74a (Documents/character-creation-vision-v1.md, 2026-01-14 brainstorm); docs/CREATIVE_BIBLE.md, commit dd97a4d.

January: one agent per character

The first build, committed on 2026-01-22, was a multi-agent system with five characters: Margaret the traditionalist baker, Steph the anxious creative director, Julian the art director who takes 47 shots, Marcus the failed novelist turned copywriter, and Devon the lazy but competent site architect. Each was its own agent class. Each character record held a profession on the team, an age, a backstory, behavioral quirks, triggers, relationships with each of the others, and internal contradictions. A memory module recorded each agent's experiences, relationship events, and emotional responses between tasks, and the product document gave each agent a persistent memory file and suggested a different model for each role.

Sources: commit 0a5d74a (backend/agents/, backend/memory/agent_memory.py); backend/data/agent_personalities.json; docs/PRD.md.

February: the sitcom formula and the name-strip test

On 2026-02-25 the Creative Bible set the format. Each recipe is a six-day story arc that publishes Sunday at 5:00 PM, told as the team's group chat, with no narrator and no bios. Its dialogue guidance drew on Friends, Seinfeld, and Cheers: verbal signatures, reactions, subtext, and comedy that comes from character rather than jokes. It also named the bar: strip the character names from a conversation, read only the messages, and ask whether you can still tell who is talking. To clear it, the Bible asked for the full character card in every dialogue generation call, plus the scene, the episode, and the conversation so far.

Sources: docs/CREATIVE_BIBLE.md, commits dd97a4d and 5eb63f6 (2026-02-25).

What the measurements showed

The voices did not clear that bar. A September read of 917 published lines over 24 weeks found every character writing in about the same register, a confident expert line of roughly two dozen words, with little variation inside any one voice. Thirty-six signature phrases produced one hit in all 917 lines. Measured from the prompt builder's own output, character material outweighed the shared rules in both prompts measured, Margaret's and Ria's, and the voices blurred anyway. The same read found the dialogue judge passing weeks I called robotic.

The judge was rebuilt to return eight structured scores, and a reply it cannot parse counts as a failure, never a default pass. Prompt changes moved to an offline method: one lever at a time, compared in blind, position-swapped pairs, with the scores recorded.

Sources: docs/conversation-lab/DIALS.md, sections 2(b) to 2(d); DECISIONS.md, entries dated 2026-09-05 (judge) and 2026-09-06 (conversation lab).

One author per scene

Once the weekly dialogue was running, each line was a separate model call, its prompt carrying the speaking character's backstory, voice guide, relationships, and recent memories. In October, production moved from generating each day's conversation one line at a time to one author writing the full scene. The evidence was one same-week run through the production handlers: the per-line generator passed the judge on the first try on 1 of 6 days, with Monday failing all three tries, and the author passed 6 of 6. That is one week, scored by a model judge, and it is not universal proof. A separate blind human comparison of Monday meetings, 14 paired picks, split 7 for the author and 7 for the old path, so human preference was not settled by it. That commit kept the per-line path in the code behind a switch. The characters, their histories, and their relationships now constrain one writer instead of six prompts.

Sources: docs/conversation-lab/DIALS.md, section 2(c); commit bf44248 (2026-10-24); docs/conversation-lab/RESEARCH_PLAN.md, study S6.

Product rules belong in code

The muffin pan has been the product's constraint since January. A prompt can ask for a muffin-pan recipe but cannot guarantee one, so Monday runs a deterministic muffin-pan form gate. Same-dish duplicates are caught by a second Monday gate on ingredient overlap, because tightening the title gate was the wrong axis.

Sources: DECISIONS.md, entries dated 2026-01-03 (the muffin pan constraint) and 2026-09-05 (ingredient overlap).

The static site underneath

Published recipe pages are committed static files, with the existing server handler as a fallback for pages published after the last deploy. Three things went wrong on the way there.

  • A first attempt pointed reader routes at files a build step was supposed to generate; the hosting configuration skipped that step, so every route returned 404 and the change was reverted.
  • A test run that wrote under a test storage prefix left that prefix in shared process state, so the live site briefly read from the test path. The fix is a context manager that restores the prefix on every exit path, including exceptions, wrapped around each scheduled handler.
  • The first live full rebuild changed the hero image on 20 of 25 published pages, because the image choice was being re-derived at build time. Chosen heroes are now pinned as data, and after the backfill 0 of 25 differ on rebuild.

Production deploys now come only from the reviewed main branch, with preview and production verification bound to that one commit.

Sources: DECISIONS.md, entries dated 2026-09-05 (static pages, pinned heroes) and 2026-10-27 (deploys); RUNBOOK.md, Incident 1.
